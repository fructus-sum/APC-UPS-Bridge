Safety first

Configuring these rules can shut down remote computers. Test key-based SSH and host-key verification, then separately verify permission to run shutdown -h now before enabling automation. Use sudo -n only for specifically authorized non-root accounts. No SSH passwords or arbitrary commands are accepted.

Only hosts explicitly approved below are affected. Every action is recorded before execution. Shutdown commands are retried a limited number of times (up to 5 attempts) until the host stops answering on its SSH port; wake packets are never repeated. A reboot cannot reset the attempt count.

Raspberry Pi / Bridge host shutdown — apcupsd

The Pi is shut down by apcupsd, independently of remote device protection. These values are read from /etc/apcupsd/apcupsd.conf. Edit Pi shutdown thresholds in Settings →

SSH key for remote hosts

Reading the bridge’s public key…

Add this public key to the account the bridge logs in as on each remote host.

Fingerprint:

Only remote hosts that list this key can be shut down by the bridge.

No SSH key found for the bridge service user.

Create one on the bridge:

sudo install -d -m 700 -o apc-ups-bridge -g apc-ups-bridge /var/lib/apc-ups-bridge/.ssh
sudo -u apc-ups-bridge ssh-keygen -t ed25519 -N '' -f /var/lib/apc-ups-bridge/.ssh/id_ed25519

Then reload this page.

How to authorize this key on a remote host
  1. Pick the account the bridge logs in as. Prefer a dedicated account allowed only to shut down the host (enable “Use sudo -n” on the device if that account needs sudo). Use an administrator account only if the host has nothing else.
  2. Add one line to that account’s authorized keys on the host. Ready-made line (replace the placeholders):
    • from= limits use of the key to the bridge’s address.
    • command= makes the key able to do nothing but run that host’s own shutdown command, whatever the bridge sends.
    • restrict disables terminals and forwarding. Very old SSH servers without restrict can use no-pty,no-port-forwarding,no-agent-forwarding,no-X11-forwarding.
    3. 

  3. Find where the host keeps authorized keys. Usually it is .ssh/authorized_keys in that account’s home directory. Some systems use a different file or manage keys in their own settings page, and some keep home directories in memory so manual edits disappear after a reboot. Use the host’s persistent method and confirm the key survives a restart. SSH servers usually require the key file and its folder to be writable only by that account.
    4. 

  4. Trust the host’s key on the bridge, then test. Run on the bridge, answer yes after comparing the fingerprint with the one the host shows, then press Ctrl+C:
    sudo -u apc-ups-bridge ssh -o StrictHostKeyChecking=ask -N -p <port> <user>@<host>
    5. 

  5. Use “Test SSH (no shutdown)” on the device. It checks login only, never runs the command, and does not prove shutdown permission. Test a real shutdown once at a safe time.
    6. 



Warning: once command= is set, ANY normal SSH login with that key runs the shutdown. Manual tests must use -N (no command, no session), for example:
sudo -u apc-ups-bridge ssh -v -N -T -o BatchMode=yes -o StrictHostKeyChecking=yes -o PreferredAuthentications=publickey -p <port> <user>@<host>
Success shows “Authenticated to”; press Ctrl+C. See docs/SSH-KEYS.md for details.

Raspberry Pi shutdown thresholds (apcupsd)
The Pi uses its own apcupsd shutdown settings, separately from remote machines. Review the active settings on the Power Rules page. The privileged helper applies validated changes without giving root permissions to the web service. Changes are refused unless the UPS is confirmed ONLINE.
apcupsd shuts the Pi down at whichever limit is reached first. Charge and runtime estimates become unreliable as UPS batteries age, so a timer of about 10 minutes is recommended for older units or original batteries.
The helper backs up the existing configuration and restarts apcupsd. Mains must be ONLINE when applying. The earliest active apcupsd shutdown condition wins; LOWBATT can also trigger shutdown.


Administrator password
Changing your password signs out all sessions, including this one.


Access and security
The standalone application defaults to 127.0.0.1:8080; the installer defaults to 0.0.0.0:8080 for LAN access. Configure a trusted HTTPS proxy or VPN before exposing management to untrusted networks.
Remote shutdown and Wake-on-LAN are available on the dedicated Power rules page. They remain disabled until explicitly approved. The Pi uses native apcupsd shutdown; configure its thresholds in Settings, independently of remote shutdown rules.
